# invoice-pipeline — 开票全流程主编排

把第 4/5/7/8 步的四个子 skill 串成一条管道，在第 6 步（税务局开票）处产出开票信息卡并暂停，等人工开完票返回 PDF 后继续。

## 完整 8 步流程定位

| 步骤 | 环节 | 负责 | 本编排是否调用 |
|---|---|---|---|
| 1-3 | 邮件检测 / 判断打回 / 接收表格 | 上游（非本项目） | ✗ 输入来自这里 |
| **4** | 企微文档查重 | wecom-invoice-query | ✅ 阶段 1 |
| **5** | 兴趣岛订单核验 | order-invoice-checker | ✅ 阶段 2 |
| 6 | 税务局开票（扫码单设备登录） | **人工** | ⭐ 阶段 3 出卡片暂停 |
| **7** | 兴趣岛新建发票记录 | invoice-create | ✅ 阶段 4（需 PDF） |
| **8** | 企微文档归档 | wecom-invoice-import | ✅ 阶段 5 |

## 何时使用

用户传入**开票信息申请表格（Excel）**或**粘贴一段开票信息文本**，要求跑开票流程时。典型说法：「跑一单开票」「开票流程」「把这些订单开票」「发票管道」。

## 输入格式

两种均可：
- **Excel 表格**：上游（老师邮件）输出的开票申请表，含订单号、抬头、税号（企业）、金额、项目名称、抬头类型（个人/企业）
- **粘贴文本**：直接粘贴一条或多条开票信息，字段同上

必填字段（每条记录）：
- 订单号（交易单号，step 7/8 都用）
- 抬头（购买方名称）
- 抬头类型（个人/企业）— 决定是否需要税号
- 金额（含税）
- 项目名称（开票项目）

企业抬头额外必填：统一社会信用代码（税号）。

## 管道流程（6 阶段）

### 阶段 0：解析输入

从 Excel / 粘贴文本提取每条开票记录，整理成结构化列表：

```
[
  { 订单号, 抬头, 抬头类型, 税号(企业才有), 金额, 项目名称 },
  ...
]
```

逐条进入阶段 1。多条记录时，先全部跑完阶段 1-2（查重+核验），再统一出卡片。

### 阶段 1：查重（调用 wecom-invoice-query，step 4）

对每条记录的订单号，调用 `wecom-invoice-query` skill 查企微文档是否已开过票。

- **已开票** → 标记 `已开过，跳过`，不进入后续阶段
- **未开票** → 继续

### 阶段 2：订单核验（调用 order-invoice-checker，step 5）

对未开票的记录，调用 `order-invoice-checker` skill 核验兴趣岛订单状态。

- **已开票** → 标记 `系统已开票，跳过`
- **未开票** → 继续
- **需人工** → 标记并提醒

### 阶段 3：出卡片 + 暂停 ⭐（step 6 人工断点）

对通过核验的记录，**在聊天里渲染开票信息卡**（模板见下方），然后 **STOP**。

告知用户：「以上是 N 张待开票信息卡，请拿去税务局开票。开好后把发票 PDF 发回来，我继续帮你录入兴趣岛系统并归档企微文档。」

**此阶段必须暂停，不要继续阶段 4。** 等用户返回 PDF 才恢复。

### 阶段 4：等 PDF + 新建记录（调用 invoice-create，step 7）

用户返回开好的发票 PDF 后，对每条记录调用 `invoice-create` skill：

- 传入：订单号、开票金额、发票类型、抬头类型、发票抬头、企业税号（企业才有）、发票 PDF 路径
- **⚠️ 安全门**：`confirm` 默认 `false`，只填不提交。需用户**显式确认**「可以点确定了」才传 `confirm=true`
- 输出：填好的截图 + `confirm_executed` 状态

### 阶段 5：归档（调用 wecom-invoice-import，step 8）

对已新建记录的订单，调用 `wecom-invoice-import` skill，把开票记录录入企微文档归档。

- 输入：开票记录 Excel（或结构化数据）
- 输出：录入成功 / 失败

### 最终输出

汇总报告：每条订单的状态（已跳过 / 已开票 / 已录入）+ 操作记录。

## 开票信息卡模板（阶段 3 渲染）

每条待开票记录渲染一张卡，4 个分区对应税务局界面：

```
📋 发票开票信息卡 — 订单号 {订单号}

① 购买方信息
  • 名称（抬头）：{抬头}              *必填
  • 税号：{企业填税号 / 个人不填}      *仅企业必填
  ✗ 不填：地址 · 电话 · 开户银行 · 银行账号

② 开票项目信息
  • 项目名称：{项目名称}              *必填
  • 金额（含税）：¥ {金额}            *必填
  ✗ 不填：规格型号 · 单位 · 数量 · 单价 · 税额
  ⓘ 税率选默认即可

③ 支付信息
  • 支付渠道：不填，留空
  • 交易单号（订单号）：{订单号}       *必填

④ 备注信息
  • 备注：订单号 {订单号}             *必填

销售方信息已预填，无需操作。
```

**判断规则**：
- 抬头含「个人」/「自然人」→ 税号不填
- 抬头是企业 → 税号必填
- 订单号填 2 次（交易单号 + 备注），必须一致

## 暂停 / 恢复机制

本编排是**多轮对话**，不是单次脚本执行：

1. 阶段 0-2 跑完后，阶段 3 渲染卡片并**停止本轮回复**
2. 用户去税务局开票（可能几分钟到几小时）
3. 用户回来发「开好了」+ 附上 PDF → 触发阶段 4 恢复
4. 阶段 4-5 自动跑完

**不要在阶段 3 后自作主张继续。** 第 6 步必须人工，PDF 是阶段 4 的硬依赖。

## 子 skill 调用约定

调用子 skill 时，把上一阶段的输出作为下一阶段输入：

| 阶段 | 调用 | 传入 | 期望输出 |
|---|---|---|---|
| 1 | wecom-invoice-query | 订单号 | 找到/找不到 |
| 2 | order-invoice-checker | 订单号 | 已开票/未开票/需人工 |
| 3 | （本编排渲染） | 通过核验的记录 | 开票信息卡 |
| 4 | invoice-create | 订单号+字段+PDF路径 | 填好截图+confirm状态 |
| 5 | wecom-invoice-import | 开票记录 | 录入成功/失败 |

子 skill 各自独立可用，本编排只是按序调用 + 传参 + 断点控制。

## 扩展接口（重要）

本编排目前只覆盖第 4/5/7/8 步。**后续会与另一个实习生的 skill 汇合**，预留以下扩展点：

- **上游汇合**：阶段 0 的输入目前靠 Excel/粘贴，未来可对接另一个实习生的「邮件解析 skill」（步骤 1-3），直接管道输入
- **step 6 自动化**：若税务局开放 API 或用云帐房 MCP（yzf-invoice-mcp-server），可在阶段 3 插入自动开票，去掉人工断点
- **批量并行**：多条记录的阶段 1-2 可并行查重核验（当前逐条）

汇合时只需在阶段 0 前加输入适配器、在阶段 3 加开票适配器，管道主体不变。

## 注意事项

1. **安全门优先**：invoice-create 的 `confirm` 永远默认 false，除非用户显式说「可以提交了」
2. **税号判断**：抬头类型决定是否填税号，阶段 3 卡片必须正确标注
3. **PDF 是硬依赖**：阶段 4 没有 PDF 无法进行，必须等用户返回
4. **查重优先**：阶段 1 查到已开票直接跳过，避免重复开票
5. **Windows 路径**：子 skill 脚本里用单反斜杠，双反斜杠会静默崩溃
